# 消费者体验改造与本机升级

目标：新用户能直接添加第一份内容，已有用户打开即可浏览；后台行为符合明确配置与用户控制。全部阶段验收通过后，构建可追溯的发布包并覆盖升级本机 Peach，保留媒体、账本、凭据与个人记录。

行为边界见 [ADR-0134](adr/0134-consumer-control-and-privacy.md)。状态必须有实际代码和验证证据，不以完成文案、隐藏入口或构建成功代替功能完成。

| 阶段 | 当前状态 | 完成条件 |
| --- | --- | --- |
| 1. 规范与仓库清理 | 已完成规范修订与定向检查 | 清除无效个人技能、命令和路径依赖；AGENTS、技能、组件契约和公开文档一致；检查不存在的引用及私有信息 |
| 2. 默认行为收敛 | 已实现，定向及桌面手机回归通过；组合验收待阶段 6 | 采集、重试、补修不操作浏览器；无凭据跳过受限能力；教程仅主动打开；无顶部催更和自动重启询问；可逆动作直接执行，错误留在原位 |
| 3. 任务范围与停止语义 | 已实现，临时数据和前端定向验证通过；组合验收待阶段 6 | 明确线程与队列关系、派发和实际完成区别；后台队列有总量与资源边界；暂停、取消、关闭能力覆盖后继及重启恢复；旧队列按当前配置恢复 |

## 阶段验收

### 规范与默认行为

- 仓库内规则引用均能取得，不要求维护者私有文件、记忆或未安装命令。
- 启动、刷新、升级、返回页面、网络错误和后台恢复均不打开教程、凭据请求或其他交互程序。
- 用户主动配置的 Cookie、Token、代理继续只用于相应来源；主动连接账号等入口保留，说明实际操作对象。
- 同步、停止读取和可逆标记不重复确认；不可逆删除、外发隐私数据和确有数据损失的动作保留相应保护。
- 来源拒绝、验证、限流和服务器超时分别记录，禁止用换浏览器或弹登录框掩盖失败。

### 后台任务

资料更新定时器只检查已主动开始的一轮；它派发的父任务成功仅表示已入队。`FollowupRunner` 执行实际后继，写账本的后继共用串行通道；任务中心与设置快照按后继的真实状态显示剩余工作。队列控制、请求前停点和重启恢复共用已持久化的暂停、取消意图。每轮固定开始时的媒体与实体范围，新的内容不会使已完成轮次自动重开。

已取得临时账本中的旧队列保留与暂停、未写回执的派发恢复、累计队列上限、固定范围、只重试失败项及取消后重启不再派发的回归证据。实际 HTTP 传输边界用替身请求验证：在途请求退出后确认暂停，下一次请求未发出，取消后保持一次请求。旧版本超量队列的兼容边界见 [运行与配置](OPERATIONS.md#升级后的资料处理)；真实安装与长队列核验仍在阶段 6。

- 将本地迁移与可选联网补修分开；用户未启用的联网能力不借升级自动开启。
- 为父任务、后继、重试和恢复建立一致的范围、停止条件及状态表达。
- 用临时账本验证长队列、失败来源、重复启动、暂停和取消；核对实际请求停止，不能只看状态字样。
- 后继尚未完成时明确显示剩余工作；派发成功不能展示为全部完成。

### 首次与日常使用

- 分开验证真正空库、筛选无结果、已有目录但未扫描、正在读取以及目录不可用，避免误判成新用户。
- 首次操作的主路径是“添加文件夹 → 选择 → 开始看到内容”；高级配置可稍后修改。
- 文件选择、默认读取范围和后台处理用途在当前位置说清；不扫描未选择目录，不为减点击而扩大权限。
- 浏览器页面与 Windows 桌面分发共用产品行为；浏览器无法选择远端目录时提供实际可用路径。
- 为首屏建立可重复的测量，记录到首项可操作内容的时间、请求依赖、点击与跨页次数；用同一数据与环境对比改造前后，不虚报性能收益。

## 发布与本机覆盖升级

所有阶段完成后冻结候选提交、版本、锁文件与构建输入。经正式测试入口验证，完成 PR 与集成，再按发布流程生成与候选绑定的安装包；实际风险对应的安装或升级检查须通过。

覆盖安装前核对本机安装来源、版本、数据根、监听端口、进程归属和正在执行的任务。使用既有备份与可续跑机制，不清空账本、媒体、凭据或行为记录。仅处理属于 Peach 本次升级的进程；升级后核对候选版本与构建标识、数据保留、主界面内容、后台任务和无自动浏览器行为。不能以源码测试代替安装包或本机升级验收。

在各阶段仍有未完成或未验证项目时，不发布为本次改造完成版，也不提前覆盖本机安装。
